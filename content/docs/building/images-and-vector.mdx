title: Images and drawing
description: Choose between decoded images, declarative vectors, imperative canvases, GPU surfaces, custom elements, and shader effects.
---

zgui has four elements for visual content. Pick one by what you have to draw:

| Element | Input | Use it for |
|---|---|---|
| [`image`](/docs/building/images) | PNG, JPEG, WebP, or GIF bytes | Photographs and raster assets |
| [`vector`](/docs/building/vector-and-canvas#draw-a-vector) | Path notation or an SVG document | Icons, logos, and other static vector art |
| [`canvas`](/docs/building/vector-and-canvas#draw-on-a-canvas) | Shapes and data series that Rust code builds | Charts, plots, editors, and generated drawings |
| [`surface`](/docs/advanced/surfaces) | A wgpu texture from another renderer | Games, video, and other GPU subsystems |

All four are ordinary elements. CSS sets their box, border, clipping, opacity, transform, and paint
order. Their content is not a child subtree.

`image` and `surface` can give layout a natural size or aspect ratio. `vector` and `canvas` have no
natural size and draw into whatever box CSS gives them. An unstyled `canvas` is 300 by 150 CSS
pixels; an unstyled `vector` can have zero area.

When none of these fits:

- A [custom element](/docs/advanced/custom-elements) is one retained widget that measures its own
  children and paints quads, paths, and glyph runs.
- A [custom shader](/docs/advanced/custom-shaders) fills, shapes, or filters a box with your own
  WGSL.

## Performance

- An image is decoded once, at the size it is displayed, and drawn from a texture.
- A surface stays in its own texture and is composited as one quad.
- `vector`, `canvas`, and custom-element paths share the vector renderer. Simple and repeated
  shapes are rasterised once or not at all, and other paths keep their GPU work while the geometry
  is unchanged. [Keep drawings fast](/docs/building/vector-and-canvas#keep-drawings-fast) has the
  rules.
