Every public component in `zgui-ui`, grouped by family, with its props and defaults. For
installation and theming, see the [overview](/docs/component-library). All names are in
`zgui_ui::prelude` unless a section says otherwise.

## Props on every component

Every component that renders an element also takes these props. The tables below leave them out.

| Prop | Type | Effect |
|---|---|---|
| `class` | `Classes` | classes merged after the component's own |
| attribute bundle | `Attrs`, `#[prop(attrs)]` | any `attr:`, `on:`, `a11y:`, `style:` the caller writes, applied after the component's own |
| `children` | `Children` or `ChildrenFn` | the content |

The caller's values are applied last, so they win:

```rust
view! {
    Button(class = "w-full", attr:data-testid = "save", a11y:label = "Save changes") {"Save"}
}
```

## How to read the tables

- `Signal<T>` means `Signal<T, LocalStorage>`, declared `into`, so a plain `T` works too.
- `Option<T>` props take a `T`; write `label = "Name"`, not `label = Some(…)`.
- `Binding<T>` is a value prop; see [Who owns a value](#who-owns-a-value).
- In the Children column, **yes** means the component takes children and **opt** means they are
  optional. **fn** means `ChildrenFn`: the content is built again each time a surface opens. **—**
  means the component takes no children.

## Who owns a value

A component with a value takes three props: the value (`value`, `checked`, `pressed`, `open`,
`index` or `page`), a `default_…`, and an `on_…change` observer. What you pass as the value decides
who owns it.

| You pass | Owner |
|---|---|
| nothing | the component, starting from `default_…` |
| an `RwSignal<T, LocalStorage>` | shared: the component reads it and writes it back |
| `Binding::controlled(read, write)` | you: the control moves only when `write` changes `read` |

Passing a read-only `Signal` is a compile error. The observer runs in all three cases, after the
value is written. Writes that arrive after the component's scope is disposed are ignored.

<Callout type="warn">
`on_change`, `on_open_change`, `on_page_change` and `on_select` are **props**, not event listeners.
Write `on_change = f`, never `on:change = f`.
</Callout>

`CellAlign` is `Start`, `Center`, `End`. `ColumnSort` is `None`, `Ascending`, `Descending`.
`GripEdge` is `Trailing`, `Leading`.

`Table` is presentational: one CSS grid with table roles. `DataTable` is driven by a model that
sorts, filters, selects, pages and virtualises.

```rust
let columns = vec![
    Column::new("item", "Item", |line: &Line| line.item.clone())
        .sortable_by(|a: &Line, b: &Line| a.item.cmp(&b.item)),
    Column::new("cost", "Cost", |line: &Line| format!("{}p", line.pence))
        .aligned(CellAlign::End)
        .sized("120px"),
];
view! {
    DataTable(
        rows = lines,
        columns = columns,
        row_id = |line: &Line| line.id.to_string(),
        label = "Invoice lines",
        selectable = true,
        filterable = true,
        page_size = 25_usize
    )
}
```

- `on_model` gives you the `DataModel<T>`: `set_sort`, `set_filter`, `go_to_page`,
  `set_page_size`, `selection`, `set_all_selected` and more. `set_sort(state)` restores a saved
  `SortState`; a state naming a missing or unsortable column is refused.
- `virtualized = true` builds only the visible rows, so `row_size` must match the row's styled
  height. Paging and virtualisation are alternatives; setting both virtualises.
- `ColumnResizer` reports the new width through `on_resize` instead of applying it. The arrow keys
  move it by `step` pixels. `edge = Leading` puts the grip on the leading edge, for a column to the
  right of a flexible one. A double click calls `on_reset`, where you can restore the column's
  default width.
- `VirtualList` builds the visible rows plus `overscan` on each side. `row_size` may be a signal;
  changing it moves the rows and the scroll extent together. The extent is capped at
  `zgui_ui::virtualize::MAX_EXTENT` (4,000,000 CSS pixels); beyond that the scrollbar maps rows
  proportionally, so use `VirtualWindow::offset_of(index)` to scroll a row into view.

```rust
            SettingsGroupLabel {"Theme"}
            SettingsItem(label = "Dark mode") {
                Switch(checked = dark, {..use_settings_item_attrs()})
            }
        }
    }
}
```

- The page list is a vertical tab list: Up/Down wrap, Home/End go to the ends, and disabled pages
  are skipped. Left and right arrows are left to the controls in the pane.
- Spread `{..use_settings_item_attrs()}` on the control so its label and description are announced.
- Pass the same `NodeRef` to `SettingsItem(control)` and to the control's `node_ref` so that
  pressing the label focuses the control.
- An item's `disabled` fades the row and blocks the pointer. Disable the control too, so assistive
  technology reports the same state.

## Toasts

| Component | Props | Children |
|---|---|---|
| `Toaster` | `corner: ToastCorner = BottomRight`, `limit: usize = 3`, `label: String = "Notifications"`, `dismiss_label: String = "Dismiss"` | yes |
| `ToastItem` | `queued: Queued`, `dismiss_label: String = "Dismiss"` | — |

Wrap your interface in a `Toaster`; it provides the toast queue as a context. Anything inside it
gets the queue with `use_toaster()`:

```rust
let toasts = use_toaster();
view! {
    Button(on:click = move |_| {
        if let Some(toasts) = toasts {
            toasts.push(
                Toast::new("Project deleted")
                    .kind(ToastKind::Success)
                    .action("Undo", move || restore()),
            );
        }
    }) {"Delete"}
}
```

| `Toast` builder | Effect |
|---|---|
| `Toast::new(title)` | a toast with a title |
| `.description(text)` | a second line |
| `.kind(ToastKind)` | `Normal`, `Success`, `Info`, `Warning`, `Error`, `Loading`; sets the icon and how urgently it is announced |
| `.duration(d)`, `.persistent()` | how long it stays (default `Toast::DEFAULT_DURATION`, 4 s), or until dismissed |
| `.action(label, f)` | a button that runs `f` |
| `.destructive_action(label, f)` | the same, drawn in the destructive fill (`ToastActionTone::Destructive`) |
| `.cancel(label, f)` | a button that dismisses the toast |

- `push` returns a `ToastId`. `replace(id, toast)` shows a new message in the same place and
  restarts its timer; use it to report progress in one toast. `dismiss(id)` and `clear()` remove
  toasts with their exit animation.
- Beyond `limit`, the oldest toasts are removed. Toasts are drawn on the toast overlay band, above
  everything else. `ToastCorner` is `BottomRight`, `BottomLeft`, `TopRight`, `TopLeft`.

## Modal surfaces

| Component | Props | Children |
|---|---|---|
| `Dialog`, `AlertDialog`, `Sheet`, `Drawer` | `open: Binding<bool>`, `default_open: bool = false`, `on_open_change` | yes |
| `DialogContent` | `dismiss_on_outside_press: Signal<bool> = true`, `dismiss_on_escape: Signal<bool> = true`, `dismiss_control: bool = true` | fn |
| `AlertDialogContent` | `dismiss_on_escape: Signal<bool> = true`, `size: AlertDialogSize = Default` | fn |
| `SheetContent` | `side: SheetSide = Right`, `dismiss_on_outside_press`, `dismiss_on_escape`, `dismiss_control: bool = true` | fn |
| `DrawerContent` | `direction: SheetSide = Bottom`, `handle: bool = true`, `dismiss_on_outside_press`, `dismiss_on_escape` | fn |
| `DialogTrigger` | `variant: ButtonVariant = Default`, `size: ButtonSize = Md` | yes |
| `DialogClose` | `variant: ButtonVariant = Ghost`, `size: ButtonSize = Md` | yes |
| `DialogHeader`, `DialogTitle`, `DialogDescription` | — | yes |
| `DialogFooter` | `close_control: bool = false` | yes |
| `DialogDismiss`, `SheetDismiss`, `DrawerHandle` | — | — |
| `SheetHeader`, `SheetTitle`, `SheetDescription`, `SheetFooter` | — | yes |
| `AlertDialogTrigger` | `variant = Default`, `size = Md` | yes |
| `AlertDialogAction` | `variant = Default`, `size = Md`, `node_ref` | yes |
| `AlertDialogCancel` | `variant = Outline`, `size = Md` | yes |
| `AlertDialogMedia` | — | yes |

`SheetSide` is `Top`, `Right`, `Bottom`, `Left`. `AlertDialogSize` is `Default`, `Sm` (narrow,
centred, answers sharing the width).

- Content is built only while open, and stays mounted until its exit animation ends.
- <kbd>Escape</kbd> closes the surface and <kbd>Tab</kbd> stays inside it. On close, focus returns to
  the trigger unless something else has taken focus in the meantime.
- `DialogTitle` labels the surface and `DialogDescription` describes it. A dialog with no title is
  announced as unlabelled.
- `dismiss_control` draws a close button in the surface's corner (`DialogDismiss`).
  `DialogFooter(close_control = true)` adds a "Close" button to the footer.
- A press outside an alert dialog does not close it, so a stray click cannot answer it.
  <kbd>Escape</kbd> still closes it.
- On `AlertDialogAction`, `AlertDialogCancel` and `DialogClose`, your `on:click` runs **before** the
  surface closes. `AlertDialogAction(node_ref)` records the button so you can focus it.
- `Drawer` has no drag-to-dismiss gesture; `DrawerHandle` is decorative.

| Component | Props | Children |
|---|---|---|

| `PopoverHeader`, `PopoverTitle`, `PopoverDescription` | — | yes |
| `Tooltip` | `open`, `default_open`, `on_open_change`, `delay: Option<Duration>`, `close_delay: Option<Duration>` | yes |
| `TooltipProvider` | `delay: Duration = 0 ms`, `close_delay: Duration = 150 ms` | yes |
| `TooltipTrigger` | — | yes |
| `TooltipContent` | `placement = Placement::TOP`, `offset: f32 = tooltip::DEFAULT_OFFSET`, `arrow: bool = true` | fn |
| `TooltipArrow` | — | — |

`Placement`, `Side` and `Align` come from [`zgui-ui-primitives`](/docs/component-library/primitives#the-placement-types).
A surface flips to the other side when it does not fit, and slides along the edge to stay on
screen.

### Tooltips

- A tooltip opens on hover, or when its trigger receives focus from the **keyboard**. Focus from a
  pointer press, from code or from an opening focus trap does not show it. <kbd>Escape</kbd> hides it
  without moving focus.
- A tooltip describes a control and cannot contain interactive content. Use `HoverCard` or
  `Popover` for that.
- `TooltipProvider` sets the delays for every tooltip inside it; a `Tooltip`'s own `delay` wins.
  Under one provider only one tooltip shows at a time: moving to the next trigger opens it at once
  and drops the previous one without an exit animation.
- The arrow points at the centre of the trigger. `DEFAULT_OFFSET` leaves room for it plus a 4 px
  gap; with the arrow on, a smaller offset is increased to fit the arrow. Set `arrow = false` to
  drop it, or place `TooltipArrow` yourself.
- Colours come from `--zui-color-tooltip`, `-tooltip-foreground` and `-tooltip-border`. By default
  a tooltip inverts the page.

| `MenuCheckboxItem` | `checked: Binding<bool>`, `default_checked: bool = false`, `on_change`, `disabled`, `close_on_select: bool = true` | yes |

A dropdown menu and a context menu differ only in what opens them. Both are filled with the `Menu…`
parts.

- The arrow keys move through the items and wrap; typing a letter jumps to a matching item;
  <kbd>→</kbd> opens a submenu, and <kbd>←</kbd> closes it and returns focus to its trigger. <kbd>↓</kbd>/<kbd>↑</kbd> on a `DropdownMenuTrigger` also open it.
- A disabled `DropdownMenuTrigger` does not open and leaves the focus order.
- A submenu opens when the pointer rests on its trigger for `menu::sub::OPEN_DELAY` (120 ms), or
  immediately when the trigger is pressed.
- `ContextMenuTrigger` opens at the pointer on a right-click or press-and-hold. To open it from
  the keyboard, call `ContextMenuPlace::current()` inside the trigger and `open_at(point)` with a
  point in window CSS pixels, such as the corner of the focused row.
- `MenuItem(inset = true)` lines a plain item up with the labels of checkbox and radio items.

`OverlayState` holds a surface's open state and its trigger and content handles.
`OverlayState::new(open, default_open, on_open_change).provide()` provides one as context; parts
below get it with `OverlayState::current()`. `zgui_ui::support` has `variant_attrs` and the editing helpers the
components use.

A modal surface is composed of these layers, from the outside in:

| Layer | From | Job |
|---|---|---|
| `Portal(layer)` | `zgui` | draws on an overlay band, outside any clipping ancestor |
| `Elevated` | `zgui-ui` | stacks a surface opened from another one above it (`--zui-overlay-depth`) |
| `Presence` | primitives | keeps the surface mounted until its exit animation ends |
| `Scrim` + `DismissableLayer` | `zgui-ui` + primitives | dims the window; closes on <kbd>Escape</kbd> or a press outside |
| `FocusScope` | primitives | keeps <kbd>Tab</kbd> inside and restores focus |
| `OverlaySurface` | `zgui-ui` | the `surface` element, its `data-state` and its role |

`AnchoredSurface` has the same layers, with a `Popper` positioner instead of the scrim, and an
optional focus trap. See [Primitives](/docs/component-library/primitives) for each behaviour.

## How a component is built

`Button`, from `crates/zgui-ui/src/button/mod.rs`, is a typical component:

```rust
#[component]
pub fn Button(
    #[prop(default = ButtonVariant::Default)] variant: ButtonVariant,
    #[prop(default = ButtonSize::Md)] size: ButtonSize,
    #[prop(into, default = Signal::stored_local(false))] disabled: Signal<bool, LocalStorage>,
    #[prop(optional)] node_ref: Option<NodeRef>,
    #[prop(into, optional)] class: Classes,
    #[prop(attrs)] attrs: Attrs,
    children: Children,
) -> impl IntoView {
    install_stylesheet("zui-button", ButtonStyle::CSS);
    let element = node_ref.unwrap_or_default();
    let variants = ButtonVariants { variant, size };
    let own = variant_attrs(variants.classes(), variants.data_attributes())
        .state(UiState::DISABLED, move || disabled.get())
        .a11y_from(A11yBinding::new(Role::Button).disabled(move || disabled.get()));

    view! {
        control(class = ButtonStyle::CLASS, node_ref = element, tabindex = Focus::Sequential,
                {..own}, {..attrs}, class = class) {
            {children.into_view_once()}
        }
    }
}
```

- The `variants!` table becomes classes and one `data-` attribute per axis
  (`zui-button zui-button--ghost zui-button--sm`, `data-variant="ghost"`, `data-size="sm"`). The
  `style!` sheet selects on those attributes.
- Hover, focus, press and disabled are CSS pseudo-classes, not signals.
- `install_stylesheet` with a fixed name installs one sheet per component type, no matter how many
  instances exist.
- Stable class names (`zui-button`, `zui-icon`, …) are safe to select on from your own sheet.
