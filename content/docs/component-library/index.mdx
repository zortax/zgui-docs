zgui has an optional component library: buttons, fields, menus, dialogs, tables, charts and more,
ported from [shadcn/ui](https://ui.shadcn.com). It is built only on zgui's public API, so anything a
component does, your own code can do too.

## Install and render a first screen

<Steps>

<Step>

**Add the crates.** List every crate you `use` in code. `zgui-ui` depends on the others for its own
use, but that does not make them available to you.

```toml title="Cargo.toml"
[dependencies]
zgui = "0.1"
zgui-ui = "0.1"
zgui-ui-tokens = "0.1"
zgui-ui-icons = "0.1"   # only if you use icons directly
```

Or run `cargo add zgui zgui-ui zgui-ui-tokens`. The crates build on stable Rust 1.90 or newer.

</Step>

<Step>

**Import the preludes.** Each prelude exports every component together with its generated props
type.

```rust
use zgui::prelude::*;
use zgui_ui::prelude::*;
use zgui_ui_tokens::prelude::*;
```

</Step>

<Step>

**Wrap the interface in a `ThemeProvider`.** Component style sheets are written with
`var(--zui-…)` tokens, and `zgui-ui` does not install the tokens itself. Without a provider, or
custom properties you declare yourself, components render unstyled.

```rust
#[component]
fn Deploy() -> impl IntoView {
    let branch = RwSignal::new_local("main".to_owned());
    let migrate = RwSignal::new_local(true);

    view! {
        ThemeProvider(scheme = ColorScheme::System) {
            Card {
                CardHeader {
                    CardTitle {"Deploy storefront"}
                    CardDescription {"Ships the branch to production."}
                }
                CardContent {
                    Input(value = branch, label = "Branch")
                    Switch(checked = migrate, a11y:label = "Run migrations")
                }
                CardFooter {
                    Button(variant = ButtonVariant::Outline) {"Preview"}
                    Button {"Deploy"}
                }
            }
        }
    }
}
```

`ColorScheme::System` follows the window's light or dark preference. To change colours, radii or
fonts, see [Tokens and theming](/docs/component-library/tokens-and-theming).

</Step>

</Steps>

A few names are not in the preludes:

- Style types (`ButtonStyle`, …) and `variants!` structs (`ButtonVariants`, …): import them from
  `zgui_ui`.
- Icons: import each constant you use, for example
  `use zgui_ui_icons::set::{chevron::CHEVRON_RIGHT, mark::CHECK};`.

`zgui_ui::prelude` does re-export `Binding` from the primitives crate, because value props take it.

## Add classes and attributes

Every component that renders an element takes `class` and any `attr:`, `on:`, `a11y:` or `style:`
attribute. They are applied after the component's own, so your values win:

```rust
Button(class = "w-full", attr:data-testid = "save", a11y:label = "Save changes") {"Save"}
```

## Control a component's value

A component with a value (`value`, `checked`, `open`, …) lets you choose who owns it:

```rust
let dark = RwSignal::new_local(false);

view! {
    // The switch owns its value, starting from the default.
    Switch(default_checked = true, a11y:label = "Notifications")
    // The switch reads and writes your signal.
    Switch(checked = dark, a11y:label = "Dark mode")
}
```

For full control, pass `Binding::controlled(read, write)`: the control moves only when `write`
changes `read`. See [Who owns a value](/docs/component-library/components#who-owns-a-value).

## How components are styled

- **Appearance is CSS.** Each component has a `variants!` table that becomes classes and one `data-`
  attribute per axis (`data-variant`, `data-size`, …), and a `style!` sheet that selects on them.
- **Interaction states are CSS pseudo-classes.** `zgui-ui` has no `hovered` or `pressed` signals;
  `:hover`, `:focus-visible`, `:active`, `:disabled`, `:checked`, `:indeterminate`,
  `:placeholder-shown` and `:invalid` do that job. Hovering a component restyles it without
  rebuilding anything.
- **Class names are stable.** Names such as `zui-button` are safe to select on from your own sheet.
- **Each component type installs one sheet.** A hundred buttons share one style sheet.

### Differences from shadcn/ui

- Not ported: the chat family (attachment, bubble, marker, message), the chip combobox,
  `PopoverAnchor`, select scroll buttons, `DirectionProvider` (there is no right-to-left layout)
  and the sidebar's mobile sheet.
- There is no `asChild`: every part renders its own element.

## The four crates

| Crate | Depends on | Provides |
|---|---|---|
| `zgui-ui` | `zgui` and the three below | the styled components |
| `zgui-ui-tokens` | `zgui` | design tokens as CSS custom properties, `ThemeProvider`, themes and presets |
| `zgui-ui-icons` | `zgui` | 23 icons and the `Icon` component |
| `zgui-ui-primitives` | `zgui` | eight headless behaviours: placement, focus trapping, roving focus, exit animations, dismissal, item order and value ownership |

Nothing in `zgui` depends on these crates. The last three are independent of each other, and
`zgui-ui` combines them: each component is a composition of primitives, a style sheet written in
tokens, and an icon where needed.

### Which crates to use

| You want | Dependencies | You write |
|---|---|---|
| finished components | `zgui`, `zgui-ui`, `zgui-ui-tokens` | component calls; appearance, keyboard handling and accessibility are done |
| behaviour only | `zgui`, `zgui-ui-primitives` | your own elements and sheets, with placement, focus trapping, dismissal, exit timing, roving focus and value ownership provided |
| nothing from the library | `zgui` | everything, from the element vocabulary up |

Tokens and icons also work on their own: `zgui-ui-tokens` with your own `css!` sheets is a design
system without `zgui-ui`, and `Icon` is a single component over the `vector` element.

## With and without the library

The same two buttons, written both ways:

<Tabs items={['With the library', 'From the element vocabulary']}>
<Tab value="With the library">

```rust
use zgui::prelude::*;
use zgui_ui::prelude::*;
use zgui_ui_tokens::prelude::*;

#[component]
fn SaveBar() -> impl IntoView {
    let saving = RwSignal::new_local(false);

    view! {
        ThemeProvider(scheme = ColorScheme::System) {
            row {
                Button(variant = ButtonVariant::Outline) {"Cancel"}
                Button(disabled = saving, on:click = move |_| saving.set(true)) {"Save"}
            }
        }
    }
}
```

</Tab>
<Tab value="From the element vocabulary">

```rust
use zgui::prelude::*;

const SHEET: &str = css!(
    ".button { display: inline-flex; align-items: center; justify-content: center;
               height: 36px; padding: 0 16px; border: 1px solid transparent;
               border-radius: 6px; background-color: #0090ff; color: #ffffff }
     .button:hover { background-color: #0588f0 }
     .button:active { transform: translateY(1px) }
     .button:focus-visible { outline: 2px solid #8ec8f6; outline-offset: 2px }
     .button:disabled { opacity: 0.5; pointer-events: none }
     .button--outline { background-color: transparent; border-color: #d9d9e0; color: #1c2024 }"
);

#[component]
fn Button(
    #[prop(into, default = Signal::stored_local(false))]
    disabled: Signal<bool, LocalStorage>,
    #[prop(into, optional)]
    class: Classes,
    #[prop(attrs)]
    attrs: Attrs,
    children: Children,
) -> impl IntoView {
    view! {
        control(
            class = "button",
            tabindex = Focus::Sequential,
            state:disabled = move || disabled.get(),
            a11y:role = Role::Button,
            a11y:disabled = move || disabled.get(),
            {..attrs},
            class = class,
        ) {
            {children.into_view_once()}
        }
    }
}

#[component]
fn SaveBar() -> impl IntoView {
    let saving = RwSignal::new_local(false);

    view! {
        row {
            Button(class = "button--outline") {"Cancel"}
            Button(disabled = saving, on:click = move |_| saving.set(true)) {"Save"}
        }
    }
}

fn main() -> Result<(), zgui::Error> {
    app().with_stylesheet(SHEET).run(|| view! { SaveBar() })
}
```

</Tab>
</Tabs>

The hand-written button already works: <kbd>Enter</kbd> and <kbd>Space</kbd> press it, because
zgui handles activation, and `state:disabled` removes it from the focus order and pointer hit
testing and reports it to assistive technology. The library's `Button` adds six variants, eight
sizes, colours that follow the theme, and one shared style sheet. For a dialog or a select, the
library adds much more: the portal, exit animation, dismissal, focus trap and placement.

## Built on the public API

`zgui-ui` depends only on `zgui` and its three sibling crates, and each sibling depends only on
`zgui`. Tests in `crates/zgui-ui/tests/downstream.rs` (and matching tests in the tokens and
primitives crates) fail the build if a crate gains another dependency or uses an internal crate.
Two more tests there reject a component that keeps its own copy of an interaction state, or that
renders an element without forwarding the caller's attributes.

The one exception in this section is [Devtools](/docs/component-library/devtools), an inspector
that reads framework internals.
